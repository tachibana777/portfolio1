ภาพรวมโครงการ
ติดตั้ง MISP 2.5.51 จำนวน 2 โหนด บน Ubuntu 24.04.5 ใน VMware เพื่อฝึกจัดการและแบ่งปันข่าวกรองภัยคุกคามระหว่างองค์กรจำลอง 2 แห่ง ได้แก่ NCSA และ ORGNAME โดยตั้งค่าการซิงก์ระหว่างเซิร์ฟเวอร์แบบ Push และ Pull

สภาพแวดล้อม
- เซิร์ฟเวอร์ 1: NCSA, IP 192.168.136.142
- เซิร์ฟเวอร์ 2: ORGNAME, IP 192.168.136.143
- ระบบปฏิบัติการ: Ubuntu 24.04.5
- แพลตฟอร์ม: MISP 2.5.51
- ระบบเสมือน: VMware

การติดตั้ง
ติดตั้ง MISP บนเซิร์ฟเวอร์ทั้งสองเครื่องด้วยสคริปต์ติดตั้งสำหรับ Ubuntu 24.04:

curl -fsSL https://raw.githubusercontent.com/MISP/MISP/refs/heads/2.5/INSTALL/INSTALL.ubuntu2404.sh | bash -s

หลังติดตั้ง ให้เข้าเว็บ MISP ของแต่ละเครื่องที่ https://<server_ip>/users/login ข้อมูลการตั้งค่าและข้อมูลเริ่มต้นของผู้ดูแลระบบถูกเก็บไว้ในไฟล์ /root/misp_settings.txt ซึ่งจำกัดสิทธิ์ให้อ่านได้โดย root เท่านั้น ควรเปลี่ยนรหัสผ่านเริ่มต้นหลังเข้าสู่ระบบ และห้ามนำรหัสผ่านหรือ Authkey ไปเผยแพร่

การจัดการผู้ใช้และองค์กร
1. เปิด Administration → List Roles เพื่อตรวจสอบบทบาทและสิทธิ์ (Role-Based Access Control: RBAC)
2. เปิด Administration → List Organisations เพื่อตรวจสอบและจัดการองค์กร
3. เพิ่มผู้ใช้ที่ Administration → Add User ระบุอีเมล ตั้งรหัสผ่าน เลือกองค์กร และกำหนด Role ตามหน้าที่
4. ใช้บัญชี Sync User สำหรับการเชื่อมต่อระหว่างโหนด และเก็บ Authkey เป็นความลับ
5. ตรวจสอบกิจกรรมระบบได้ที่ Logs → Audit Logs
6. ตรวจสอบสถานะและการวินิจฉัยระบบที่ Administration → Server Settings & Maintenance → Diagnostics

การตั้งค่าเชื่อมต่อระหว่างโหนด
1. ไปที่ Sync Actions → Remote Servers แล้วเลือก New Server
2. กรอก Base URL ของ MISP โหนดปลายทางและกำหนด Instance Name เพื่อให้ระบุโหนดได้ง่าย
3. เลือก Organisation Type และใส่ Authkey ของบัญชี Sync User ฝั่งปลายทาง
4. ตั้งค่ารูปแบบการแบ่งปันเป็น Push และ Pull ตามวัตถุประสงค์ของแล็บ
5. กำหนด Push Rules และ Pull Rules ให้เหมาะกับขอบเขตการแบ่งปัน
6. ตัวเลือก Publish Without Email และ Allow self-signed certificates ใช้ตามสภาพแวดล้อมแล็บเท่านั้น โดยใบรับรองแบบ self-signed ไม่เหมาะกับการเชื่อมต่อระบบจริง
7. บันทึกการตั้งค่า แล้วใช้ Run เพื่อตรวจสอบการเชื่อมต่อ จากนั้นติดตามงานเบื้องหลังในหน้า Jobs

ฟีดข่าวกรองภัยคุกคาม
ตรวจดูรายการฟีดได้ที่ Sync Actions → Feeds ซึ่งแสดงชื่อผู้ให้บริการ รูปแบบข้อมูล สถานะ Enabled และสถานะ Caching ภาพหลักฐานของแล็บแสดงว่า CIRCL OSINT Feed เปิดใช้งาน ส่วนฟีดอื่นที่เห็นปิดอยู่ และสถานะ Caching ยังปิด จึงบันทึกผลเป็นการตรวจสอบการตั้งค่าฟีด ไม่ใช่การยืนยันว่าดึงหรือนำเข้าข้อมูลจากทุกฟีดแล้ว

เหตุการณ์ แท็ก และ TLP
ตรวจดูรายการเหตุการณ์ในหน้า Events ซึ่งมีข้อมูลจากองค์กรผู้สร้างและองค์กรเจ้าของ พร้อมแท็กประเภท OSINT, MITRE ATT&CK และ Galaxy ตัวอย่างในภาพมีการอ้างอิงเทคนิค MITRE ATT&CK และแท็ก TLP

Traffic Light Protocol (TLP) ใช้ระบุขอบเขตการเผยแพร่ข้อมูล:
- TLP:RED — จำกัดเฉพาะผู้รับที่ระบุ
- TLP:AMBER — แบ่งปันอย่างจำกัดตามความจำเป็น
- TLP:GREEN — แบ่งปันได้ในชุมชนที่เกี่ยวข้อง แต่ไม่เผยแพร่สู่สาธารณะ
- TLP:CLEAR — เผยแพร่ต่อสาธารณะได้

ผลการเรียนรู้
- ติดตั้งและดูแล MISP สองโหนดบน Ubuntu
- จัดการผู้ใช้ บทบาท และองค์กร
- ตั้งค่าการซิงก์ข้อมูลระหว่างโหนดและติดตามงานในคิว Jobs
- ตรวจสอบรายการฟีดและสถานะการเปิดใช้กับการทำ Cache
- อ่านเหตุการณ์ที่กำกับด้วยแท็ก OSINT, MITRE ATT&CK, Galaxy และ TLP
- ใช้ Audit Logs และหน้า Diagnostics เพื่อตรวจสอบระบบ

ขอบเขตและข้อจำกัด
เป็นแล็บส่วนตัวที่จำลองการแบ่งปันข่าวกรองระหว่างสององค์กร ไม่ใช่ระบบใช้งานจริง ภาพฟีดที่บันทึกไว้แสดงว่ายังไม่ได้เปิด Cache จึงไม่กล่าวอ้างว่ามีการนำเข้าข้อมูลจากฟีดเป็นผลลัพธ์ที่ยืนยันแล้ว การตั้งค่าใบรับรองแบบ self-signed ใช้เฉพาะเครือข่ายแล็บและควรเปลี่ยนเป็นใบรับรองที่เชื่อถือได้ก่อนใช้งานจริง
